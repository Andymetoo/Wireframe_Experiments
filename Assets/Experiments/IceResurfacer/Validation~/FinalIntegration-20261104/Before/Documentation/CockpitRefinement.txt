Scope and reference

feedback and rear glance. The supplied Zam_New_1/2/3 images guide the corrections.
The local 526 manual was reviewed: PDF page 46 shows the brush between the axles,
behind the front wheel; page 12 provides the vehicle dimension diagrams. Those
references do not specify an exact brush pivot or cockpit reach dimension.
The dimensions below are Aurora calibration, not manufacturer CAD measurements.

Mechanical changes
The brush pivot parameter moves the hinge, arm, compliant extension, motor,
brush and roller together. The simulated contact still uses that same pivot,
arm length and deployment angle, including existing board compliance. There is
no independent visual offset. Core snow-clearing behavior is preserved.

The steering column now owns the wheel hub. A connected lower shaft, universal
joint, upper shaft, foot and support replace the previous disconnected/flat
arrangement. The dashboard and complete lamp assembly follow the forward hub.
The column foot is seated on the existing operator platform, with its fixed
support connected to the lower shaft; a runtime contact check prevents a gap.
The narrower fixed support also clears both pedals throughout their travel.
Wheel animation retains the existing five-to-one relationship to actual vehicle
steering. Wheelbase, track, steering limits and driving dynamics are unchanged.

The blade screw assembly owns its fixed bearings, spindle, index and rotating
handwheel. Its new position is behind and between the adjacent water bearings.
The same 3.5-turn adjustment, screw setting and Core state remain authoritative.
Both water stems are taller; independent quarter-turn travel and mechanical
stops remain. Labels read FLOOD WATER and WASH WATER. The picker targets the
actual grip with a small tolerance, avoiding empty space above the nearer valve.
The complete breaker guide/guard/rod/handle moves beside the hydraulic bank.
Its click operation and 18 cm down-and-return animation remain intact.

The Machine Geometry Editor exposes these parameters through the existing scene
calibration. Its selectable preview and runtime use the same builder. Save the
launch scene to persist edits. No second geometry or simulation system was added.

Interaction and camera
The existing moving-part ray picker also supplies hover selection. Cached URP
MaterialPropertyBlocks apply a subtle amber tint to the selected moving assembly,
with a stronger tint during dragging. Fixed plates and adjacent controls retain
their own appearance. The existing HUD hint identifies the selected control.
Release restores the original property blocks. No fullscreen render feature,
material clone per hover, extra selection ray system or new runtime component
is needed.

Held Left Shift now looks over the RIGHT shoulder at +160 degrees yaw and
22 degrees downward pitch. Release smoothly restores the exact saved orientation
and eye offset. WASD remains independent. Right Shift retains machinery and
precision modifiers. Q/E/C, RMB look, R standing and X recenter remain operational.
Q points 30 degrees farther forward along the left working edge, at -65 degrees
yaw / 75 degrees down, to frame both the forward brush and trailing conditioner.
The existing seated origin, eye-height setting and left inspection lean remain.
E framing uses the updated real grip, blade-rim and breaker extents.

Reproduction
Run the core harness from the repository root:
  dotnet run --project Assets/Experiments/IceResurfacer/Validation~/IceResurfacer.Validation.csproj --configuration Release -p:UseSharedCompilation=false

Stage the disposable Unity project:
  powershell -NoProfile -ExecutionPolicy Bypass -File Assets/Experiments/IceResurfacer/Validation~/StageUnityValidation.ps1 -UpdateOnly
Run the existing isolated harness, using a unique log filename:
  powershell -NoProfile -ExecutionPolicy Bypass -File Assets/Experiments/IceResurfacer/Validation~/RunIsolatedUnity.ps1 -Action RunBatch -LogName Cockpit-refinement-repeat.log
The installed Unity licensing client must be reachable. Heavy validation runs
must be serial; wait for the owned process to exit before staging or launching
the next run. The harness enters actual Play Mode and exits itself.

Preservation and limits
Only this experiment was edited. No branch, commit, push, original project-wide
setting, shared package or unrelated experiment was changed. The user's original
Editor was not switched or stopped. Existing dirty workspace work was retained.
AuditCockpitPreservation.py checks source/staged hashes, metadata, GUIDs,
outside-experiment status and selected byte-identical handoff files.
Audit outputs:
  Validation~/Cockpit-refinement-preservation.txt
  Validation~/Cockpit-refinement-source-sha256.txt

The first integrated capture run exhausted native texture resources. The
editor-only capture helper now restores render targets in finally and destroys
temporary textures immediately, instead of deferring many captures to the end
of one Editor update. The final runtime run completes without that failure.
Earlier diagnostic logs remain available and are not presented as passing runs.

Default geometry is validated. Bounds in the Geometry Editor do not certify
every combination of custom dimensions; recheck clearances after adjustments.
These automated camera renders and kinematic checks do not establish physical
operator reach or manufacturer authenticity. No fresh performance benchmark or
audio calibration was part of this focused pass.
