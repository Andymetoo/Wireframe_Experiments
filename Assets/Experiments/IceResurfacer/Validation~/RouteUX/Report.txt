AURORA R-54 / ROUTE MANAGER, KEYPAD AND GPS VISIBILITY REFINEMENT

Operator workflow
Record: NUMPAD 8 opens Route Manager. Enter a name, RECORD NEW ROUTE and drive.
        NUMPAD 9 also begins recording directly. A red recording banner is shown.
Save:   NUMPAD 9 stops and saves automatically, or click STOP & SAVE.
Load:   NUMPAD 8 > LOAD SAVED ROUTE > select by name/date/length > USE AS GPS.
        NUMPAD 7 toggles it. The selected raw recording is fitted automatically.
Documentation/RouteOperator.txt contains the concise three-action guide.

What changed
Primary Route Manager now presents large buttons, readable names/dates/lengths,
an obvious active GPS name and selection, scrollable saved routes and a full
preview. Technical statistics/footprint layers/manual recovery remain behind
Diagnostics / Advanced. The existing Training Route Editor and its spline
geometry are preserved; EDIT ROUTE opens/prepares the selected editable fit.

Raw saved routes no longer require an Editor conversion before following.
The existing fitter and constrained-tangent implementation create a separate
editable guide in Guides/AutoFit. The checksummed raw file remains untouched.
Both actual supplied operator recordings (152.9 m and 93.5 m) fit successfully.
Unusable/too-short takes report preparation errors and retain the active route.
The built-in reference and labeled test remain explicit library choices.

Save always generates a new readable filename with UTC timestamp and random
suffix. Repeated names create unique copies; existing files are never silently
overwritten. Save As New Copy can copy the selected saved route. Rename writes
a separate versioned/checksummed RouteNames.json display-name index, preserving
the original route bytes and filename. Delete requires a per-file confirmation;
Cancel changes nothing. The active GPS can remain in memory if its saved file
is deliberately deleted. Recovery drafts remain separate and untouched.
OPEN ROUTES FOLDER opens the current library only on the user's click.

The filesystem-dialog discrepancy came from the Editor raw inspector's
Save Portable Copy action, which used EditorUtility.SaveFilePanel. It is now
explicitly labeled EXPORT TO LOCATION (opens file picker). Ordinary in-game
Save consistently writes a unique copy directly and displays a saved message.

Keypad controls use Input System's actual Numpad7/Numpad8/Numpad9 keys.
F5/F6/F7 remain compatibility aliases. Number-row machinery controls retain
their original implementation. Route shortcuts are suppressed while name fields
or confirmation dialogs own text input. Virtual-device tests exercise raw keypad
events with Num Lock key state present and absent and with native mouse focus.
No global OS keyboard state was changed; physical laptop/USB Num Lock behavior
still deserves a manual hardware check.

Guidance disappearance investigation
The unmodified reference reproduced a stop at approximately 19.705883 m,
near the first direction-change boundary (137 total contexts). Its look-ahead
was clipped to the active/next context and direction, then the final four meters
were hidden. A tiny adjacent reverse context could also hold progress while
the vehicle had already changed direction.
Progress now accepts only the immediately adjacent direction change near its
shared endpoint with compatible heading. Automatic transitions do not acquire
an unrestricted next leg. All sequence/distance/travel-budget guards remain.
The reference probe now traverses all 137 contexts to 1568.674 m without manual
rejoining. Actual recorded-pose tests cross 18 and 7 contexts respectively.
Closely overlapping/coincident loop tests retain their original no-skip behavior.

The world and Surface Survey use the same confirmed progress and a 12.192 m
(40 ft) forward window, crossing context boundaries. Completed portions leave
the window. The map keeps its ice classifications and current-position arrow,
adding a thin magenta route, direction chevron, upcoming turn and active leg.

Default world styling is vivid magenta/fuchsia with a dark border and fading
ends; the ribbon lies flat on the ice. Color/opacity controls are in Advanced.
A restrained screen continuation appears only when the nearest opaque-mesh
ray hit belongs to the actual machine/conditioner and is closer than the ground
guide point. Opaque walls/stands block it; menus suppress it. Queries use an
isolated local physics scene with cached mesh colliders and no rendering or
simulation actors. Degenerate effect triangles are filtered in private query
meshes; source meshes and the main physics scene are unchanged. The screen
transform respects the scaled Game-view canvas. No always-on-top world pass
was introduced. Sources/colliders are cached, not created each frame.

Remaining limitations
Fitting/load is synchronous and can pause briefly on large takes. Physical/rink
constraint failures still need optional editing; fitting never changes the raw
trajectory. Major sequence skips still use explicit recovery. The visibility
query meshes represent the current authored opaque arena/machine; arbitrary new
opaque scene geometry added during Play requires a query refresh/restart. Thin
masked continuation is advisory. Footprint diagnostics retain their prior 20 cm
geometry/quantity limitations. Color/pace/overlap should be calibrated manually
with the actual operator. Native hidden-window presentation warnings prevent
claims about focused-window input latency or subjective hardware readability.

No branch, commit or push. No original saved route was deleted or rewritten
during implementation; destructive operation tests used new disposable copies.
